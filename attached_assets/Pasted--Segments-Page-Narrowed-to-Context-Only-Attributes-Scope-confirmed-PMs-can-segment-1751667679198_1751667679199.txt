### “Segments” Page — **Narrowed to Context‑Only Attributes**

**Scope confirmed:**
*PMs can segment players only by *static or contextual* user properties (e.g., `utm_source`, `tier`, `country`, `device_os`, `install_age`).*
**No behavioural or KPI filters** (revenue, play‑time, churn) in V‑1.
Level‑/object‑specific attributes remain an *Advanced* toggle for power users—but still parameter values, **not metrics**.

Below is an updated, developer‑ready spec.

---

## 1 · Attribute Whitelist

| Category                     | Allowed keys                                                                     | Source              |
| ---------------------------- | -------------------------------------------------------------------------------- | ------------------- |
| **Acquisition**              | `utm_source`, `utm_campaign`, `ad_group`, `creative_id`                          | SDK traits          |
| **User Tier**                | `tier` (e.g. *newbie*, *mid‑core*, *pro*)                                        | Game server / login |
| **Geography**                | `country`, `region`                                                              | SDK traits          |
| **Device / App**             | `device_os`, `app_version`                                                       | SDK traits          |
| **Lifecycle**                | `install_age_days`, `first_session_date`, `returning_player` (bool)              | Backend calc        |
| **Advanced (Object params)** | any flag value sent in last 30 days (e.g., `level_number`, `difficulty_setting`) | Event payloads      |

> **No** revenue, LTV, play time, session count, etc.

## 3 · Segment Builder Modal

| Step                  | UI Details                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1 · Name**          | Text field (required).                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **2 · Define Rules**  | **Simple Rule Builder** (always visible):<br>• Attribute dropdown (shows only whitelist)<br>• Operator dropdown (`=`, `≠`, `IN`, `NOT IN`, `<`, `>` where numeric)<br>• Value input / multiselect chips.<br>Logical groups: `AND` lines; an **“Add OR group”** button adds separate box.<br><br>**Advanced toggle** (collapsed):<br>• “Include object parameters” → second builder, attributes auto‑listed from manifest/event schema.<br>• Grey badge “ADVANCED” in summary if used. |
| **3 · Review & Save** | Show rule chips + live estimate *“≈ 14 % of daily players (3 250 users)”*.<br>Yellow warning if `< N` users; **Save Segment** CTA disabled if estimate unknown.                                                                                                                                                                                                                                                                                                                       |

**Live estimate call**: `POST /segments/estimate` returns `count_daily`.

## 7 · API & DB

### `segments` table

| column            | type                       |
| ----------------- | -------------------------- |
| `segment_id` (PK) | uuid                       |
| `name`            | text                       |
| `rules_json`      | jsonb   // conforms to DSL |
| `is_advanced`     | bool                       |
| `created_at`      | timestamptz                |

### Endpoints

```
GET  /v1/segments
POST /v1/segments          { name, rules_json }
POST /v1/segments/estimate { rules_json } → { users_daily: int }
```

*Experiences table* stores `segmentId` instead of raw rules when applicable.

## 8 · Pros & Cons Recap for PM

| Pros                                                                 | Cons (with guardrails)                                                                                       |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| **Fast reuse**: define once, pick everywhere.                        | Segment list can bloat → show “Used In” to weed unused, allow archive.                                       |
| **Keeps wizard uncluttered**; quick builder still inline for ad‑hoc. | Live estimate necessary to prevent teeny segments → implemented.                                             |
| **Advanced still available** but safely hidden.                      | Advanced segments need dev data → show empty state “No level parameters detected” instead of empty dropdown. |
