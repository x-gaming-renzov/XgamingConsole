### Revised UX Specification — **Multi‑Object Experiences (no metaphors)**

*Objective: Let a PM compose one Experience from several FTUE objects, save it as a draft template, or launch it to a campaign with optional scheduling & auto‑rollout.*

---

## 1 · Core Terminology (stable)

| Concept                                       | Label in UI    |
| --------------------------------------------- | -------------- |
| Level / Popup / Flag                          | **Object**     |
| A specific combination of object variants     | **Experience** |
| Acquisition source                            | **Campaign**   |
| Library of all objects detected from manifest | **Objects**    |

(No “ingredients / cocktails / pantry” wording.)

---

## 2 · Updated Create‑Experience Wizard (5 steps)

| Step                           | Purpose                                          | Navigation hints                                                                              |
| ------------------------------ | ------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| **1 · Select Objects**         | Multi‑select one or more objects to include.     | Sidebar *“Selected (N)”* shows running tally.                                                 |
| **2 · Configure Variants**     | Define variant values for EACH object.           | Accordion for each object; progress bar “Object 2 / 3”.                                       |
| **3 · Traffic Split**          | Decide overall control vs experience percentage. | Slider 0‑100 %. If >1 variants per object, matrix auto‑generates combinations (hard‑limit 8). |
| **4 · Target & Schedule**      | Pick campaign and set release rules.             | Existing campaign list or quick create; schedule start/stop; optional auto‑rollout criteria.  |
| **5 · Review & Save / Launch** | Final summary; save as draft or launch.          | Dual CTAs: **Save Draft** · **Launch Experience** (disabled if schedule in future).           |

### Step‑by‑step UI details

#### 1 · Select Objects

* Card grid or table with checkboxes.
* Right‑side sticky panel: shows currently selected objects; “Remove” inline.
* *Next* disabled until ≥ 1 object selected.

#### 2 · Configure Variants

* Each object panel contains:

  * Read‑only control values.
  * Variant A fields prefilled with control; PM edits differences.
  * “Add Variant” button (max 3 variants per object).
* Validation: highlight out‑of‑range values.

#### 3 · Traffic Split

* **Global slider** — 0 % (full control) ↔ 100 % (full experience).
* If multiple variants create >8 recipe combos → show warning “Too many combinations; deselect variants or objects”.

#### 4 · Target & Schedule

* Campaign picker (search + daily traffic figure).
* Optional quick builder: utm\_source, label.
* Date‑time pickers for start / stop.
* Auto‑rollout toggle → input uplift %, minimum users.

#### 5 · Review

* Summary card listing:

  * Objects (with chip count).
  * Variants per object.
  * Campaign & schedule.
  * Traffic split bar.
* **Save Draft** stores with status=Draft.
* **Launch Experience** triggers schedule; status=Active if start ≤ now else Scheduled.

## 4 · API / Data Model

```jsonc
POST /v1/experiences
{
  "name": "Level 5 + Popup boost",
  "campaignId": "facebook_ads",
  "startAt": "2025‑07‑08T09:00:00Z",
  "endAt": null,
  "autoRoll": { "uplift": 0.05, "minUsers": 5000 },
  "trafficSplit": { "control": 0.5, "experience": 0.5 },
  "objects": [
    {
      "objectId": "level_5",
      "variants": {
        "control": { "starting_coins":100 },
        "A": { "starting_coins":150 }
      }
    },
    {
      "objectId": "welcome_popup",
      "variants": {
        "control": { "title":"Welcome" },
        "A": { "title":"Claim your gift!" }
      }
    }
  ]
}
```

* SDK unchanged: `/login` returns map per object; client queries `Pulse.getVariant(objectId)`.
